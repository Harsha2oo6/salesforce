2. Normalize Event Contracts (Base Inputs → Dynamic Form)
2.1 Canonical event shapes
All base inputs (including the new multi-select) emit:
valuechange and fieldblur with detail = { field, value }.
2.2 Simplify middle layers
dynamicFormField:
Forwards fieldvaluechange and fieldblur using the same detail it receives (no re-deriving field).
dynamicFormRenderer:
Assumes { field, value } and just re-dispatches to dynamicFormContainer.
2.3 Container integration
dynamicFormContainer.handleFieldValueChange / handleFieldBlur consume { field, value } consistently for all field types, including the new multi-select dropdown.
3. Centralize Validation (Including Date & Multi‑Select)
3.1 Single source of truth for errors
Only dynamicFormContainer.errors[fieldName] holds validation errors.
Base inputs are purely presentational: they receive error-message and render it.
3.2 Date constraints in container
baseFormInputDate:
Removes internal errorMessage mutation on blur.
Emits fieldblur with { field, value }.
dynamicFormContainer.validateFieldValue / validateAllFields:
For date fields, call validateDateConstraints and merge any error message into errors[fieldName].
